# Archive

Executed implementation plans. Each one was a step-by-step script for work that
is now in `main`, so they describe what was done rather than what the code is,
and they date quickly: paths, function names and counts in them refer to the
tree as it stood when they were written.

Kept because they record the order work happened in and the decisions taken
mid-flight, which is occasionally the only place an odd-looking choice is
explained.

**The design documents in `../specs/` are not archived.** They are the standing
account of why the code is shaped as it is — the mechanisms, the measurements
behind them, and the alternatives rejected — and the handoff notes in `..`
point at them. Read a spec to understand the code; read a plan here only to
understand how it got built.
